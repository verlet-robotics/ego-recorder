  <action>
Rewrite main.cpp to support both GUI and headless modes via IPresenter polymorphism. Preserve the existing three-thread pipeline architecture.

**CLI changes (cxxopts):**
- Add `--headless` boolean flag (default false)
- Add `--config` string flag (path to TOML config file, default "")
- Keep all existing flags (--output, --session-name, --duration, --quality, --zstd-level, --queue-size, --warmup)
- Load config file FIRST via load_config(config_path), then override with any explicitly-provided CLI flags

**Config + CLI merge logic:**
- Load Config from file if --config provided, else use defaults
- CLI flags override config values when explicitly provided (use cxxopts `count()` to detect explicit vs default)
- For headless mode: if no --session-name provided, auto-generate timestamp-based name (per locked decision)
- For headless mode: create date-based output directory: `config.output_dir + "/" + YYYY + "/" + MM + "/" + DD + "/"` using std::filesystem::create_directories (per locked decision)

**Presenter creation:**
- `std::unique_ptr<IPresenter> presenter`
- If --headless: `presenter = std::make_unique<HeadlessPresenter>(config, shutdown_callback)`
- Else (GUI mode): `#ifdef HAVE_GUI` guard, create GuiPresenter with config and FOUR recording callbacks (on_start_recording, on_stop_recording, on_session_name_changed, on_reconnect_requested). If HAVE_GUI not defined and --headless not passed, print error "GUI not available (built without WITH_GUI)" and exit 1.

**Recording lifecycle callbacks for GUI mode:**
- `on_start_recording`: create new FileWriter with make_output_path(), write_header(), set recording flag
- `on_stop_recording`: finalize current writer, reset recording flag, reset stats
- `on_session_name_changed`: update session_name variable
- `on_reconnect_requested`: trigger the full reconnect sequence -- destroy current pipeline, wait 500ms, create new pipeline, configure_and_start(), call presenter->on_camera_reconnect(), open new recording file if was recording before disconnect. This is the critical wiring that connects the GUI Reconnect button to actual camera recovery. The lambda passed to GuiPresenter must capture the necessary state (pipeline unique_ptr ref, config, writer, etc.) to perform the full destroy+recreate sequence.

**Main loop refactoring:**
The current main loop structure is:
1. Init camera
2. Init writer
3. Start capture thread
4. Start writer thread
5. Stats loop in main thread
6. Shutdown

New structure:
1. Parse CLI + config
2. Setup signal handling
3. Init camera (configure_and_start)
4. Create presenter (GUI or headless)
5. presenter->start()
6. For headless: immediately open FileWriter, write_header, start capture+writer threads, begin recording
7. For GUI: start capture thread for preview (push frames to presenter via update_frame), but don't open FileWriter until user clicks Start
8. Main loop: call presenter->tick() in a loop. Also feed capture frames to presenter->update_frame() for GUI display. Check shutdown_flag.
9. On recording start (GUI callback): open writer, start writer thread
10. On recording stop (GUI callback): finalize writer, stop writer thread
11. On shutdown: join threads, finalize writer if recording, presenter->shutdown(), camera stop

**USB disconnect/reconnect recovery:**
In the capture thread, wrap poll_frame() in try/catch for rs2::camera_disconnected_error:
- On disconnect: call presenter->on_camera_disconnect()
- GUI mode (per locked decision): do NOT auto-retry. Set a flag. The GUI will show a "Camera Disconnected" banner with a "Reconnect" button. When user clicks Reconnect, the on_reconnect_requested callback (passed to GuiPresenter constructor) fires and main triggers the reconnect sequence: destroy pipeline, sleep 500ms, recreate pipeline, configure_and_start, on_camera_reconnect, start new recording file.
- Headless mode (per locked decision): auto-retry loop every 2 seconds:
  1. camera.reset() (fully destroy old pipeline object)
  2. sleep 500ms
  3. camera = make_unique<RealSensePipeline>(), configure_and_start()
  4. On success: finalize current recording file, open new recording file (per locked decision: new file on reconnect), call presenter->on_camera_reconnect(), break retry loop
  5. On rs2::error: continue retrying (camera not yet available)
- Other rs2::error types: treat as fatal, set shutdown_flag

**Disk full handling (per locked decision):**
- HeadlessPresenter already monitors disk in tick() and calls on_request_shutdown when low
- In main loop: when presenter->tick() returns false, initiate clean shutdown sequence
- Finalize current file, stop recording, exit process cleanly
- systemd Restart=on-failure will restart the service

**Update CMakeLists.txt:**
- Note: config.cpp was already added to the ego-recorder target by Plan 02-01. Do NOT re-add it.
- Add src/presenter/headless_presenter.cpp to the ego-recorder target (always)
- Conditionally add src/presenter/gui_presenter.cpp when WITH_GUI is ON
- Ensure link order is correct (imgui_glfw_opengl3 only when WITH_GUI)

**Key architectural decisions:**
- The capture thread ALWAYS runs (even in GUI mode before recording starts) to feed live preview frames
- The writer thread only runs when actively recording
- FileHeader assembly stays in main.cpp (preserving the Phase 1 decoupling decision)
- Stats object is shared between threads via atomic counters (unchanged from Phase 1)
